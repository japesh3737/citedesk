# Security notes

Implemented: parameterized SQL; Zod body/query validation; published-only public access; server admin RBAC; bcrypt hashing; opaque expiring revocable sessions; HttpOnly SameSite=Strict cookies, Secure in production; session regeneration; exact configured Origin verification on every mutation, fail closed when Origin is absent; JSON-only writes; cross-site Fetch Metadata rejection; no CORS permission; Helmet headers and production CSP; capped requests/body sizes; generic errors without stack traces; rate limits; text-only chat; safe Markdown; redaction and configurable retention.

Origin design follows https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html. SameSite alone is not the CSRF defense. Command-line writes also require the configured Origin header. No secrets in browser storage or source. Production rejects HTTP public origins and requires external PostgreSQL. Random request IDs accompany safe errors; request bodies and cookies are not logged.

Threats: unauthenticated admin access, stored/reflected XSS, SQL injection, CSRF, credential guessing, draft leakage, prompt injection and content poisoning. Direct and indirect prompt-injection tests assert abstention; no LLM exists to grant tools or disclose server context. The source-content detector is a heuristic and cannot guarantee all malicious text is identified. Admin-approved malicious facts can still poison extraction. Human content review is required.

Residual risk: regex redaction is imperfect, user-provided secrets may escape detection, and feedback can be repeated by clearing cookies. Rate limits are memory-local and reset on restart. Proxy trust is intentionally disabled. No MFA, password reset, account lockout, distributed throttling, secret vault, complete security audit or compliance certification. Markdown links use react-markdown safe URL defaults; article output is not raw HTML. Production CSP requires actual deployment testing. External PostgreSQL adapter and HTTPS reverse proxy were not exercised here. GET path validation relies on parameterized lookups with bounded public slugs; admin ID length/shape validation is not uniform. Audit records are not transactionally coupled to article updates. Do not deploy without reviewing these limits.

Dependency audit results and executable test evidence are in VALIDATION.md. Dev CSP is disabled for Vite; never expose development mode publicly.

## Google identity integration

Optional Google sign-in uses OAuth authorization code + S256 PKCE, browser-bound single-use state, nonce, verified ID tokens via the official Google library and an explicit administrator email allowlist. In production, allowlisted addresses are provisioned as ADMIN if no account exists; existing roles and passwords are preserved. Permanent subject bindings prevent replacement with another Google identity. Gmail or verified Google Workspace identities only. Google cannot promote existing non-admin users or create public users. Google tokens are not retained; OAuth state/verifier records last at most ten minutes before expiry and are purged on subsequent authorization starts. The pending-flow cookie is HttpOnly, SameSite=Lax, Secure in production; application sessions retain Strict settings. Token/signature verification uses Google network endpoints when enabled. See GOOGLE_SIGN_IN.md for setup, test evidence and residual limitations. Live provider login remains unverified without operator OAuth credentials.
